# 工作台导航与统计修复

日期：2026-10-11。

## 原因与修改

- “我的任务”把 `flt-mine` 设置为 `assigned`，但工作台只调用 `switchTab('tasks')`，重新请求时仍带着该条件。因此不是没有请求数据，而是返回了同一份筛选结果。
- 任务预设切换现在先清除普通与高级筛选，再设置当前预设，最后发起一次列表请求；显式点击工作台恢复全部可见任务，侧栏只高亮当前入口。
- 自动轮询不调用预设切换，因此仍保留用户当前筛选和编辑草稿。
- 汇总接口的 `overdue`、`upcoming` 实际可能是最多 20 条任务明细。前端原先直接写入文本，产生 `[object Object]`。现在兼容数字字段；遇到明细数组时，使用同一可见范围的任务查询返回的 `total`，避免被 20 条上限截断。

应用修改仅涉及 `TeamToDo V1.1/static/index.html`，兼容当前 EXE，无需重新打包。没有修改后端、实际配置或业务数据库。修复验证阶段未提交或推送 Git，后续按用户要求纳入 V1.2 上传。

## 验证

使用独立临时数据库、真实 HTTP 服务和无头 Chrome：

```text
node tests/workbench_navigation.cjs
node tests/workbench_navigation.cjs --exe
node tests/live_refresh.cjs
```

新回归在修改前复现“我的任务 → 工作台”仍只有一条任务；修改后源码与现有 EXE 模式均通过：

- 工作台恢复全部 22 条测试任务，筛选恢复默认。
- 我的任务、即将到期、已逾期、部门待认领之间切换不残留上一个入口条件。
- 当前导航只高亮一个入口。
- 逾期 21 条、即将到期 1 条显示正确数字，不显示对象或截断为 20。
- 浏览器无脚本异常，工作区业务数据库 SHA-256 未变化。

原实时刷新回归另外检查跨会话更新、草稿保护、网络恢复、搜索保留和隐藏页面行为。

## 使用

正在打开的网页需要按 `Ctrl+F5` 加载更新后的页面。若另一台电脑使用独立应用副本，需要同步其 EXE 同目录的 `static/index.html`。
